## 検出可能なアプリを公開

ビルド済みチェックアウトで実行します。

```sh
OMOCHI_SERVICE=python-example uv run --project examples/python examples/python/app.py
```

別のターミナル:

```sh
bun run omochi-ui hub
```

**http://127.0.0.1:5555/** でダッシュボードを作り、Surfaceを追加して保存します。同梱のアプリは`OMOCHI_SERVICE`があるとUnixソケットで公開します。Hubは必要ならローカルGatewayを起動しますが、検出対象のアプリ自体は起動しません。

## upでプロセスを構成

`omochi-ui up --open [FILE]`はプリセットに宣言したサービスとHubを起動します。quickstartの設定は`examples/quickstart/omochi.toml`です。最初のレイアウトは保存するまで一時的です。Ctrl+Cで`up`が所有するプロセスを停止します。

## 配置とライフタイム

Surfaceは個別に配置できるビューです。ダッシュボードの保存は配置の保存であり、アプリの実行状態の保存ではありません。サービス停止中は利用できず、アプリの再起動でSurfaceが戻ります。`hub`と`dev`の既定ポートはともに5555なので、片方を止めるかポートを変えます。

詳細は[CLI](../../reference/cli/)と[設定](../../reference/configuration/)へ。

## 保存したダッシュボードを共有する

`omochi-ui hub --remote`でネイティブHubを起動し、ボードを保存して **ダッシュボードを共有** を開きます。`https://app.omochi.fyi/`のクライアントはirohでこのHubに接続するため、Hubを起動したままにします。

共有リンクには、**アプリ操作**と**レイアウト編集**を個別に許可できます。既定はどちらも不可です。リンクを知っている全員が、転送先も含め同じ権限でアクセスできます。ブラウザごとの登録は不要です。

レイアウト編集者が変更できるのは名前・タイトル・位置・サイズです。ビューの追加・削除、接続元の変更、ボード削除、共有管理にはオーナー権限が必要です。アプリ操作は業務データを変更する場合があります。権限変更はリンクを取り消して再発行してください。

旧v1の公開リンクと個別共有は利用できません。アップグレード後にリンクを再発行してください。オーナー登録とGatewayの信頼設定は維持されます。

共有対象は保存済みボードに追従し、オーナーが追加したビューは表示され、削除したビューは引き下げられます。ボード削除でアクセスも終了します。受信者は許可されたSurfaceの状態全体と公開画像を閲覧できます。接続元が停止中なら利用できません。

**アクセス権を取り消す…** から共有リンク全体を取り消します。稼働リスナーの接続破棄を待ち、記録の削除後でも確認に失敗すればエラーです。ブラウザーの接続記録を削除するだけではHub上の権限は取り消せません。

全体の管理には[オーナー接続](../remote/#ホストされたブラウザーから接続する)を使います。ブラウザーidentity、保存失敗、再接続、Flutterクライアントについては[共有ガイド](https://github.com/omochi-ui/omochi/blob/main/docs/dashboard-sharing.md)を参照してください。
