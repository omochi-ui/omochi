## ビューを配置する

[最初のUI](../../start/first-ui/)に従ってHubとツールを起動するか、[SDKガイド](../sdks/)で自分のアプリを公開します。

Hubでダッシュボードを作成し、**Add view**からSurfaceを選びます。タイトル・位置・サイズを調整して保存してください。ひとつのアプリが公開する複数のSurfaceも、別々に配置できます。

Hubは実行中のアプリを検出します。アプリ自体は起動しないので、利用中は公開元のプロセスを動かしておきます。停止したアプリのビューは利用不可になり、同じサービスIDで再起動すると戻ります。保存するのは配置であり、アプリの実行状態ではありません。

## 複数のプロセスをまとめて起動する

プロジェクトの`omochi.toml`にサービスと配置を宣言すると、次のコマンドでまとめて起動できます。

```sh
omochi-ui up --open
```

最初の配置は一時的です。**Save as dashboard**で編集可能なダッシュボードとして保存します。Ctrl+Cでこのコマンドが起動したプロセスを停止します。設定例は[CLIリファレンス](../../reference/cli/#up)を参照してください。

## 保存したダッシュボードを共有する

```sh
omochi-ui hub --remote
```

ボードを保存して **ダッシュボードを共有** を開きます。**アプリ操作**と**レイアウト編集**を個別に許可でき、既定はどちらも不可です。作成したリンクを受信者へ渡してください。リンクを知っている全員が、転送先も含め同じ権限でアクセスできます。

受信者が使う間はHubと元のアプリを起動しておきます。共有は保存済みボードに追従し、オーナーが追加・削除したビューも反映されます。受信者は対象Surfaceの状態全体と公開画像を閲覧できます。ボードを削除すると共有も終了します。

レイアウト編集で変更できるのは名前・タイトル・位置・サイズです。ビューの追加・削除、接続元の変更、ボード削除、共有管理にはオーナー権限が必要です。アプリ操作を許可すると、元のアプリのデータを変更する場合があります。

権限を変えるにはリンクを取り消して再発行します。**アクセス権を取り消す…** は、そのリンクを持つ全員のアクセスを終了します。接続記録の削除だけでは権限は取り消せず、送達済みのデータや実行済みの操作も取り消せません。エラーが出た場合は[トラブルシューティング](../../understand/troubleshooting/#アクセス権の取り消しがエラーになる)を参照してください。

全体を管理するには[オーナー接続](../remote/#ホストされたブラウザーから接続する)を使います。[モバイル・デスクトップアプリ](../mobile/)でも共有リンクを開けます。

## 接続を切り替える・保存する

サイドバーの **接続** に、オーナー接続と共有ダッシュボードが並びます。
接続を選び、その下からダッシュボードを選択します。元の接続に戻ると、
直前のダッシュボードが復元されます。共有とオーナーの権限は別です。
ハブを管理するには、一覧のオーナー接続を選んでください。

接続の **…** から、名前の変更・IDの確認・保存済み情報の削除ができます。
画面上部の接続名の横には、現在の接続に対する **接続を記憶**・**アプリで開く**・**切断** を表示します。
**接続を記憶** は、リンクとアクセスに必要な秘密情報をこのブラウザに
保存し、タブを閉じても開けるようにします。保存しない共有は現在のタブ内だけで
利用できます。保存しても権限は増えず、保存済み接続を削除してもハブ側の
アクセス権は取り消されません。記憶するとボタンが **記憶済み** に変わります。
**接続を記憶** と **アプリで開く** は、共有リンクで接続しているときに利用できます。

狭い画面では **接続を切り替え** から一覧を開きます。画面上部の **切断** を押すと、
別のタブでブラウザIDを使って接続できます。オーナー招待が開いている場合は、
先に完了するか閉じてください。エクスポート・ボード表示・削除は **その他** に
あります。ダッシュボードの削除には引き続き確認が必要です。
未接続時は中央の一覧から接続を選べます。ブラウザIDの確認とリセットは、その下の **接続の詳細** にあります。
